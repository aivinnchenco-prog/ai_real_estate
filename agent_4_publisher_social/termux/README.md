# Termux-раннер для Publisher social

Телефон сам себе раннер: Termux управляет **этим же** телефоном через ADB по
loopback. Ни компьютера, ни Raspberry Pi, ни USB, ни root. Телефон стоит дома,
сам ходит в Notion за очередью и публикует. Ты — где угодно.

## Что ставится

| Файл | Роль |
|---|---|
| `bootstrap.sh` | разовая установка окружения |
| `bin/connect_self.sh` | подключение телефона к самому себе (ищет новый порт) |
| `bin/run_loop.sh` | вечный цикл: wake-lock → connect → publisher_social → отчёт |
| `bin/notify.sh` | отправка уведомлений в Telegram |
| `bin/ctl` (ставится как `pub`) | пульт: start/stop/status/logs |
| `service/boot_start.sh` | автозапуск после перезагрузки (Termux:Boot) |

## Установка

**1. Приложения — только из F-Droid, не из Play Store.**
Версии в Play Store заморожены и ломаются на новых Android.
- Termux
- Termux:Boot (автозапуск после ребута)
- Termux:API (wake-lock)

**2. На телефоне включи режим разработчика:**
Настройки → О телефоне → «Номер сборки» тапнуть 7 раз.

**3. Положи проект на телефон и запусти bootstrap.**

Вариант через git (удобно обновлять):
```bash
termux-setup-storage
export PROJECT_GIT_URL="https://…/publisher-social.git"
bash "Publisher social/termux/bootstrap.sh"
```

Вариант без git (скопировать папку вручную):
```bash
termux-setup-storage
mkdir -p ~/publisher-social
cp -r /sdcard/Download/"Publisher social"/* ~/publisher-social/
bash ~/publisher-social/termux/bootstrap.sh
```

**4. Впиши ключи** в `~/publisher-social/.env`:
```
NOTION_API_KEY=secret_…
NOTION_DB_ID=…
```

**5. Первое подключение к себе.** Bootstrap запустит `connect_self.sh` сам.
При первом разе понадобится один раз спарить: Настройки → Для разработчиков →
Беспроводная отладка → «Подключение с помощью кода». Скрипт спросит порт и
6-значный код. Дальше порт находится автоматически.

## Проверка перед боем

```bash
pub test
```
Покажет, видит ли Termux телефон, и прогонит очередь в dry-run — без единой
публикации. Если тут `ok` и объект в очереди распознан — всё сходится.

## Работа

```bash
pub start      # запустить фоновый раннер
pub status     # 🟢/🔴 + устройство + хвост лога
pub logs       # следить за логом в реальном времени
pub stop       # остановить
pub once       # один цикл вручную (для отладки)
pub notify     # тест Telegram
```

После перезагрузки телефона раннер поднимется сам — Termux:Boot вызовет
`boot_start.sh`, тот переподключится (порт после ребута другой!) и запустит
`pub start`.

## Telegram-уведомления

Настраивается в `~/.publisher/runner.env`:

```
TG_BOT_TOKEN=123456:AAA...
TG_CHAT_ID=123456789
DEVICE_LABEL=phone-1
```

Токен — у @BotFather (`/newbot`). Chat ID — напиши боту любое сообщение и
открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, возьми `chat.id`.

Проверка: `pub notify` — должно прийти тестовое сообщение.

Что приходит:

| Событие | Пример |
|---|---|
| старт / остановка | 🚀 Раннер запущен |
| успех | ✅ A_20260725_001: опубликован один канал + подтверждённая ссылка |
| провал | ❌ A_20260725_001: успешно 2, провалов 1 + строки `[FAIL]` |
| зависание | ⏱ Цикл повис и прерван через 30 мин |
| нет ADB | ⚠️ Нет ADB-подключения к телефону |
| низкий заряд | 🔋 Заряд 18% |
| вечерняя сводка | 📊 Сводка за 2026-07-27: опубликовано 12, провалов 1 |

Тумблеры: `NOTIFY_OK`, `NOTIFY_FAIL`, `NOTIFY_IDLE`, `DAILY_DIGEST_HOUR`
(`-1` выключает сводку). `DEDUP_MINUTES` не даёт одному и тому же алерту
приходить чаще раза в час — иначе падающий канал завалит чат.

В live-режиме отчёт после фактического прогона канала обязателен. Если Telegram
временно недоступен, сообщение атомарно сохраняется в
`~/.publisher/pending_channel_report.txt`. Следующий live-запуск сначала
повторяет доставку и не начинает новую соцсеть, пока предыдущий отчёт не
доставлен. Поэтому перед live обязательно должен успешно пройти `pub notify`.

## Настройка поведения

`~/.publisher/runner.env`:

| Параметр | Смысл |
|---|---|
| `RUN_CMD` | что вызывать; обычно `queue --live` (он также потребляет due scheduled) |
| `POLL_SECONDS` | пауза между опросами Notion (по умолч. 300) |
| `QUIET_START` / `QUIET_END` | тихие часы, публикаций не будет |
| `WAKELOCK` | 1 — держать телефон бодрым |
| `STOP_AFTER_CHANNEL` | 1 — после одного live-канала сохранить/отправить отчёт и остановиться |

`queue --live`, `publish --live`, `publish-all --live`, `publish-retry --live`,
`publish-scheduled --live` и `publish-chain --live` выполняют не больше одного
фактического канала за процесс. Служебный `skip` публикацией не считается:
раннер не сообщает его как успех и не останавливается из-за очистки устаревшей
scheduled-записи.

Внешний UI-lock реализован через `flock`: после crash/SIGKILL ядро освобождает
его автоматически. Внутри Python дополнительно действует `data/publisher.lock`
для команд, работающих с телефоном и state.

Лимиты на аккаунт, паузы между объектами и таймзона живут в конфиге самого
проекта (`config/publisher.json`), Termux их не дублирует.

## Что реально ломается (и как понять)

**Порт отладки слетел после ребута.** Самая частая беда loopback-схемы.
Лечится само: `connect_self.sh` ищет новый порт через mDNS перед каждым
циклом. Если не нашёл — в логе будет «не смог подключиться», и `pub connect`
попросит один раз спарить заново.

**Беспроводная отладка выключилась.** Некоторые прошивки гасят её после
долгого простоя или обновления. Тогда `pub status` покажет «нет loopback».
Зайди в Для разработчиков и включи снова — дальше подхватится.

**На нескольких телефонах становится неудобно.** Каждый Termux-раннер живёт
сам по себе: обновлять и чинить нужно каждый отдельно. Уведомления это
частично лечат (по `DEVICE_LABEL` видно, какой аппарат пишет), но когда
телефонов больше трёх — это сигнал переезжать на схему «мини-ПК/S7 +
телефоны по USB» с центральным сервером.

**Doze всё равно душит.** Если раннер засыпает несмотря на wake-lock:
Настройки → Приложения → Termux → Батарея → «Без ограничений».

## Важно про сам телефон

- Отключи автообновление приложений (Play Store → Настройки → выкл).
  Обновление Instagram/TikTok меняет UI и ломает сценарии.
- Отключи автообновление Android — оно перезагружает телефон и роняет
  loopback-пару в самый неудобный момент.
- Держи на зарядке. `svc power stayon usb` не даёт экрану гаснуть, но
  постоянный экран + заливки сажают батарею в ноль за часы без питания.
